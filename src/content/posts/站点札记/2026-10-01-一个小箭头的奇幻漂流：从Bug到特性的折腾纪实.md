## 起因：一次对「高反差胶囊」的垂涎

在折腾博客的路上，折腾往往始于一次“多看了一眼”。

前阵子逛到 [MmzMing 大佬](https://github.com/MmzMing) 的博客（仓库：[MmzMing/my-blog](https://github.com/MmzMing/my-blog)）时，我被他顶部导航的悬停交互深深吸引住了：
- 鼠标滑过时，那个高对比度的白色胶囊药丸高亮贴地滑过；
- 展开的子菜单不再是各个导航项各自生硬地弹出一个小方块，而是整条导航共享一个**单一下拉面板**，随着鼠标在「文章」「动态」之间横向滑动时，面板与小三角在下方以平滑缓动曲线行云流水般跟随切换。

对比我原先微弱且看不太清的导航底色，这套高反差的设计不仅辨识度拉满，而且视觉质感极其高级。

于是，我决定把它移植到自己的博客里。然而我万万没想到，这一趟移植之旅，最后竟演变成了一场围绕**一个像素级小箭头**的奇幻大冒险。

## 突发“灵异现象”：下沉偏位与祖传卡死

移植的核心逻辑很顺利：共享面板、双 `rAF` 调度平滑过渡、Swup 生命周期接管，一切按部就班。然而，当把鼠标移到带子菜单的标签（比如「动态」或「文章」）旁边的小箭头上时，奇妙的灵异现象接连浮现了：

### 现象一：它居然会“往下掉并歪向右下角”？
正常情况下，菜单展开时，下拉箭头应该在原地正中心优雅翻转 180° 指向正上方。然而在我的页面上，鼠标一悬停上去，这个小箭头不仅没有居中翻转，反而**微微向下沉了一截，甚至还俏皮地歪到了右下角，而且依然朝下指**！

### 现象二：一点就卡死，非要点空白处才肯复位？
更离奇的是，如果我用鼠标轻轻点击了这个标签按钮，这个小箭头就会彻底“凝固”在翻转状态，任凭我把鼠标移到天涯海角也纹丝不动。要想让它复位？必须老老实实在页面随便找个空白区域点一下。

我一开始以为是我移植时写漏了什么代码，结果顺藤摸瓜去看了原版博客（包括团子大佬和 MmzMing 大佬的站点）——好家伙！原来大家或多或少都有这个点击后焦点残留的祖传现象！

## “这不是 Bug，这是 Feature！”

面对第一个现象，如果换作专业的前端程序员，第一反应八成是：*“这定位绝对算偏了，成何体统，赶紧居中修掉！”*

可惜我并不是什么程序员，而是一个纯粹迷恋动效质感、享受博客折腾乐趣的普通人。

看着那个被规规矩矩改回正中翻转 180° 的严肃小箭头，我心里反而泛起了嘀咕——

**不对啊，原先那个往下沉、微微歪向右下角的效果，怎么看着那么顺眼呢？！**

普通的菜单翻转箭头千篇一律，而那个不经意间跑偏的微下沉，在鼠标 hover 时就像是机械键盘轴体被手指轻点按压的物理回馈一样，带着一种难以言说的机械生命力。

:::note
**需求正式确立：**
1. 鼠标悬停在母标签时，我想要保留那个**向下微沉偏位**的独特机械质感；
2. 但是！当鼠标顺着滑进弹出的子菜单选项（比如滑到「分类」）时，箭头必须在上方稳稳**翻转朝上指（`^`）**，明确指示当前正处于展开态；
3. 并且，那个点击后永久卡死、必须点别处才能恢复的祖传 Bug，必须斩草除根！
:::

## 探案现场：现代 CSS 的“数学巧合”

为什么之前的代码里会出现那种“悬停时下沉朝下，滑入菜单却又翻转朝上”的魔幻行为？

深挖到底层源码后，我被现代 CSS 规范背后的**数学巧合**惊呆了：

1. **旧文件的独立属性：**
   在主题旧版的 `dropdown.css` 里，有一句 `@apply rotate-180`。在 Tailwind CSS v4 下，现代浏览器直接把它编译成了 CSS 原生独立属性：
   ```css
   rotate: 180deg;
   ```
2. **新文件的矩阵变换：**
   而在我新写的 `dropdown-menu.css` 中，为了做位移动画，写了传统的：
   ```css
   transform: translateY(-50%) rotate(180deg);
   ```
3. **巧合的诞生：**
   在现代 CSS Transforms Level 2 规范中，**独立的 `rotate` 属性与 `transform` 里的 `rotate()` 是会累加生效的**！

于是，物理化学反应发生了：
- **当鼠标悬浮在母标签上时**：同时命中 `:hover`，两个 180° 旋转叠加：
  $$180^\circ + 180^\circ = 360^\circ = 0^\circ \text{（指向下方）}$$
  再加上 `translateY(-50%)` 的位移，刚好把小箭头推到了右下角偏位，形成了那个美丽的“下沉动效”！
- **当鼠标滑入弹出的「分类」时**：鼠标脱离了母标签，旧文件的 `:hover` 瞬间失效，独立属性 `rotate: 180deg` 归零；但此时面板仍处于展开态（`.is-dropdown-open`），新文件的 `transform` 单独生效，旋转变成了纯粹的 $180^\circ$，箭头便瞬间在上空翻转朝上了！

至于点击卡死的问题，真凶也浮出了水面：HTML 中的 `<button>` 元素在被鼠标点击后，会默认获得浏览器的持久聚焦（Focus）。CSS 规则里写了 `:focus-within`，导致鼠标离开后容器依然匹配焦点态，箭头自然就被锁死在了展开姿态。

## 驯化：从巧合走向严谨的两段式动效

既然搞清了所有来龙去脉，就不能再让两套旧 CSS 文件瞎撞运气了，必须把这套“机缘巧合”收编成**可控、严谨、优雅的确定性特性**。

### 1. 拆解双态状态机
我们彻底移除了旧文件中的全局冲突规则，在 `dropdown-menu.css` 中清晰定义了两个互斥阶段：

```css
.dropdown-container .dropdown-arrow {
  transform: translate(0, 0) rotate(0deg);
  transition: transform 0.2s cubic-bezier(0.25, 0.46, 0.45, 0.94),
              color 0.2s ease;
}

/* 阶段一：鼠标悬浮在母标签上时，恢复经典大幅度下沉偏位动效（指向下并下沉偏移 8.8px、向右微歪 2px） */
.dropdown-container:hover .dropdown-arrow {
  transform: translate(2px, 8.8px) rotate(0deg);
}

/* 阶段二：鼠标滑入弹出的下拉面板时，恢复经典大幅度向上浮起（-8.8px）并翻转朝上指（^） */
.dropdown-container.is-dropdown-open:not(:hover) .dropdown-arrow,
.dropdown-container:focus-visible .dropdown-arrow {
  transform: translate(0, -8.8px) rotate(180deg);
}
```

:::tip[生产构建踩坑：告别脆弱的双重属性]
在本地开发环境（Vite dev）下，浏览器会分别执行独立的 `rotate: 180deg` 与 `transform: rotate(180deg)` 的数学叠加；但部署到生产环境（`pnpm build`）时，现代 CSS 压缩器为了极限精简体积，在遇到相同 `transform` 声明时会自动合并选择器，并把独立的 `rotate` 属性清洗掉，导致生产环境下两态都变成了单一的朝上指（`^`）。

因此，最严谨的做法是**直接在 `transform` 内部显式声明确切的双向偏移（悬停下沉 `translate(2px, 8.8px)`、滑入上浮 `translate(0, -8.8px)`，正好等于 1.1rem 箭头尺寸的一半 50%）与旋转角度**，让两态的声明值彼此独立互斥；同时避免重复叠加 Tailwind 的垂直居中 `translate: 0 -50%`，彻底杜绝被构建压缩器误伤，确保开发与生产 100% 绝对一致！
:::

### 2. 根除点击卡死
告别盲目的 `:focus-within`，拥抱更现代的 `:focus-visible`（仅为键盘 Tab 导航保留无障碍轮廓），并在鼠标点击触发器时主动让其脱焦：

```typescript
const trigger = target?.closest<HTMLElement>("[data-dropdown-trigger]");
if (trigger) {
  // 鼠标点击触发按钮后主动脱焦，避免留存原生 :focus 导致箭头无法随鼠标离开复位
  trigger.blur();
}
```

## 成果与感悟

改完刷新页面的一刹那，手感前所未有的舒畅：
- 鼠标滑到「文章」上，小箭头轻轻一沉，仿佛一个被微微按下的机械按钮；
- 鼠标顺势向下滑向「分类」「归档」，小箭头在头顶伴随着白色胶囊高亮轻巧地一翻，向上指引着当前所处的层级；
- 移开鼠标，一切悄然收回，没有一丝一毫的焦点残留，也不需要再去点空白处化解尴尬。

前端世界最迷人的地方或许就在这里：**很多最初看起来荒诞不羁的 Bug，剥开表象之后往往是规范与算力的奇妙共振**。

如果你足够好奇，不急着把它一棒子打死，而是坐下来推导它的成因，你就会发现：它不仅能被修复，更能被驯服成属于你个人博客独一无二的温度与灵魂。
